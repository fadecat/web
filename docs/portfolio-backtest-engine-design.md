## 二、十处必须在动手前定死的细节

### 1. Benchmark 口径（硬阻塞，仍未解决）

方案把"与基准比较"当成默认可用的东西，但**基准是什么口径还没定**。

- 【代码事实】`index_daily_quote` 的易方达源（`index_eod_price`）**只有 close 一个字段**，从接口命名与字段判断是**价格指数（PRICE_RETURN）**，不含股息再投入。
- 红利类资产年股息率常年 4%~6%，占长期收益的一半以上。用 PR 序列当基准，**会系统性低估红利基准收益**，量级（4~6pp/年）远大于多数策略效果，且**方向偏乐观**——会人为抬高"多资产组合跑赢红利""再平衡有正贡献"这类结论。

**建议**：Benchmark 优先用**对应 ETF 的 HFQ 序列**（`research_daily_bar_adjusted`，后复权已含分红再投）。若只能用指数序列，界面必须强制标注 `PRICE_RETURN`，且"相对红利超额"这一列要挂警示。
**验证方法**：取红利指数除息密集日，看点位是否跳空下跌——跳空即 PR。这个验证成本极低，建议先做。

### 2. 交易成本必须按资产类别分档，不能统一费率

方案说"第一版不做成本、第二版加"——这个顺序我反对。**成本口径不定，"再平衡贡献 +1.1%"这种数就是噪音。**

> ❌ **2026-09-19 更新：本段及其费率表作废。** 已确认**不计交易成本**（用户明确），复刻目标韭圈儿本身也是零成本口径，且回归验证已全部 PASS。保留此表仅作实盘参考（评估真实摩擦时仍需这些费率）。详见 `docs/funddb-portfolio-algorithm.md`。

| 资产类别 | 印花税 | 佣金 | 过户费 | 备注 |
|---|---|---|---|---|
| A股个股 | 卖出 0.05%（2023-08 减半后） | 双边约万2.5，常有 5 元最低 | 双边 0.001% | 最低佣金对小额调仓影响很大 |
| ETF / LOF | **免** | 双边约万2.5 | **免** | 显著低于个股 |
| 可转债 | 免 | 低（万0.5 以内量级） | 免 | — |
| 场外基金 | — | 申购费 1 折后约 0.1%~0.15% | **赎回费按持有期阶梯**（<7 天 1.5%，<30 天常见 0.75%） | 阶梯费率对高频再平衡是致命的 |

【判断】实现为 `cost_profile` 参数对象（按 `asset_class` 分档 + 全局乘数），默认给「保守 / 中性」两档，**每次 Run 都记录所用口径**。费率随政策变化，必须可配置，不能硬编码。

### 3. "再平衡贡献"不能在同一 Run 内分解出来

方案要求把"再平衡贡献 +1.1%"单独列出来。方向上对，但**数学上它不是一项可与资产贡献相加的独立收益项**——再平衡改变的是权重路径，不是收益来源。

可行做法：

- **资产贡献**（严格可加）：用**期初持仓权重**分解。单日 `R_p,t = Σ w_i,t-1 × R_i,t − cost_t`，逐日精确成立；跨期因复利不可直接相加，需 Carino / Grap linking 或改用对数收益分解后链接。
- **再平衡净效应**：必须与 **Buy & Hold 对照 Run**（同起点权重、不再平衡）相减得到，已含成本。
- **要分离"再平衡毛利"与"成本拖累"**：需要 **三个 Run** —— (a) BH 零成本、(b) BH 含成本、(c) Rebalance 含成本。三个才能把成本单独切出来。

> ❌ **2026-09-19 更新：本段作废。** 已确认**不计交易成本**，故 (b)(c) 两个含成本 Run 取消，"再平衡贡献" = **(a) 不平衡零成本** 与 **(c) 再平衡零成本** 两个 Run 的净值比。详见 `docs/funddb-portfolio-algorithm.md`。

【判断】第一版就提供"一键生成三 Run 对照"，成本很低，但能把方案里那个问题真正回答清楚：**分散的价值 vs 再平衡的价值 vs 成本的拖累，各占多少。**

> ❌ **同上，改为两 Run 对照**（不平衡 vs 季平衡 vs 年平衡）。

### 4. 场外基金"按当日净值成交"存在前视偏差

方案建议研究模式"按当日净值成交、忽略确认延迟"。这里有个口径陷阱：

- 场外基金 **T 日净值盘后才公布**，T 日盘中不可能知道。用 T 日净值成交 = 用了 T 日盘后信息在 T 日下单，构成前视。
- 场内资产（股票/ETF）用 T 日收盘价成交是成立的（收盘价 T 日已知，可用收盘竞价成交），两者不能套同一规则。

【判断】场外基金默认 **T+1 成交**（T 日信号 → T+1 净值成交）。实现上就是把成交价序列 `shift(1)`，成本几乎为零，但避免了口径污染。
另外：场外基金净值**目前无任何数据源**【代码事实：全库无净值表】。建议第一版**预留接口但不支持**，等数据源接进来再开；不要为了凑资产类型而降低口径标准。

### 5. 跨市场日历：并集与交集要用在不同地方

方案说"不能简单 inner join"——对，但需要更精确：

- **净值路径**：用**并集日历**（所有资产生效日的并集），停牌/非交易日资产价格**前值填充（ffill）**、当日该资产收益记 0。用交集会吃掉大量日期，尤其在跨市场时。
- **再平衡触发日**：用**交集**（最后一个共同交易日），因为调仓要求所有腿都能成交。
- **更关键的一条**：【判断】**优先用境内上市的 QDII ETF 代理海外资产**（如纳指 ETF 513100 在 A 股交易），这样所有腿天然落在 A 股日历上，跨日历问题直接消失。直接引入海外指数序列会同时带来日历错位 + 汇率 + 时差收盘三项麻烦。
- 若将来真做跨市场：【判断】"同一自然日收盘价同时成交"是**研究假设**，必须在 Run 元数据与界面上显式标注。

### 6. 阈值再平衡（THRESHOLD）的定义需要收敛

方案给了"偏离 ±5pp 才调"，但有三个未定项，会显著改变换手：

1. **偏离度量**：绝对百分点 vs 相对比例。绝对 5pp 对小权重资产不敏感（目标 5% 的资产偏到 10% 才触发，等于翻倍）；【判断】默认绝对 pp，可选相对。
2. **触发后调到哪**：回到目标权重（full）还是只调回阈值边界（partial）。【判断】默认 full，partial 作为高级选项。
3. **与日历组合**：方案说"每季度检查一次 + 偏离 5% 才调"——需要把**检查日**与**触发条件**分离成两个正交参数：`check_frequency` × `trigger`。

### 7. 缺失数据与不同上市起点（方案完全没提）

回测区间 `2015-01-01 ~ 2026-09-18` 很可能超出部分资产的数据起点。例如【待确认】红利低波100（930955）指数发布约 2017-05，黄金 ETF / 纳指 ETF 约 2013 年上市。

必须定规则，否则会静默产出错误净值：

- 【判断】**默认"截断法"**：实际回测起点 = `max(各资产首个有效日)`，并在结果页**逐资产显示有效区间**。
- **禁止"权重再分配"**（把缺失资产的权重按比例分给其余资产）——这引入前视（未来才知道谁会缺失），且让不同起点的 Run 之间不可比。
- 若某资产中途退市/停牌：ffill + 标记，不要静默剔除。

### 8. 现金与第一版边界

方案提到要真实模拟"现金"。【判断】第一版**不设现金账户**：

- 做现金拖累需要货币基金/存款利率序列——又是一个新数据源。
- 简化：交易成本**直接从净值扣除**（等价于按权重等比例减持），不做现金余额。误差量级远小于成本口径本身的假设误差。
- 全额投资假设要在界面明示。

同理，**最小交易单位**（A股 100 股 / 场外 1 元起）第一版用**分数份额**（研究模式），不模拟碎股。

### 9. 执行时序必须写死（防前视）

净值连续性的标准做法，需在文档与代码中固定：

```
T 日：用 ≤T 的数据计算目标权重 → 以 T 日收盘价成交（扣除成本）
      → T 日收益率必须先计入【旧持仓】，再换仓
      → 新权重从 T+1 起生效
```

这与方案"然后更新下一期持仓"一致，但值得显式写进规格，避免实现时把 T 日收益算到新权重上（那是前视）。

另外：再平衡日期**必须用交易日历表**，不能 `resample('M').last()`——后者得到的是自然月末，非交易日会错位。现有 `research_trade_calendar` 正是为此准备的。

### 10. 存储与并发：NAV 不落 SQLite

- 【代码事实】数据库是 SQLite（WAL，`busy_timeout=5000`），当前约 24MB。
- 【判断】`backtest_nav` 若按日×资产落明细会迅速膨胀。建议：**NAV 明细存文件（parquet/csv），DB 只存 Run 元数据 + 摘要指标**。
- 回测是 CPU 密集的 pandas 循环，**必须异步执行**，否则与 APScheduler 的抓取任务争锁。

## 三、建议的接口契约

### 统一价格序列接口

```python
@dataclass(frozen=True)
class SeriesQuery:
    asset_id: str
    start: date
    end: date
    return_type: Literal["PRICE", "TOTAL_RETURN"]   # 必填, 不允许默认

@dataclass(frozen=True)
class PriceSeries:
    asset_id: str
    return_type: str
    dates: list[date]
    nav: list[float]          # 口径内可比净值(已按 return_type 处理)
    adjusted_nav: list[float] # 用于收益计算(含分红/复权)
    source: str               # 数据来源, 必须回传
    adj_mode: str | None      # HFQ / NAV / NONE
    coverage: tuple[date, date]
    warnings: list[str]       # 例: "仅 PRICE_RETURN, 不含股息再投入"
```

**关键点**：`return_type` 必填且不允许默认；`warnings` 必须向上传递到 UI。这样"口径混用"在数据源头就被挡住，而不是靠用户自觉。

### 组合与规则定义

```python
@dataclass
class PortfolioSpec:
    name: str
    legs: list[Leg]                 # {asset_id, weight, cost_profile_override?}

@dataclass
class RebalanceRule:
    check_frequency: Literal["NONE","DAILY","WEEKLY","MONTHLY","QUARTERLY","SEMIANNUAL","ANNUAL"]
    trigger: Literal["CALENDAR","THRESHOLD"] | None
    threshold_pp: float | None      # 绝对百分点
    threshold_mode: Literal["FULL","PARTIAL"] = "FULL"

@dataclass
class CostProfile:
    preset: Literal["ZERO","CONSERVATIVE","NEUTRAL","CUSTOM"]
    by_asset_class: dict[str, CostLeg]
    settlement: Literal["T0","T1"] = "T0"   # 场外基金建议 T1
```

### Run 元数据（复用研究回放范式）

```
run_id            BT-20260919-0012
portfolio_hash    组合定义(资产+权重)哈希
rebalance_rule    再平衡规则哈希
cost_profile      成本口径哈希
return_type       各资产口径摘要
start / end       请求区间 与 实际有效区间(截断后)
engine_version    引擎版本
data_as_of        数据截止日
input_hash        上述全部输入的组合哈希 —— 改任一参数即为新 Run, 不覆盖旧结果
```

与现有 `ResearchReplayRun` 一致：**参数即身份**。

**两条会影响实验设计的现实约束：**

1. **复权序列只有 5 个标的、且自 2021 起。** 想跑 2015 起的全天候回测，当前数据面不够。好消息是扩容成本极低——`config/research.yaml` 加一行即可，抓全历史。
2. **511010 是 5 年期国债 ETF，久期偏短。** 经典全天候里的"长期债券"需要长久期（10Y+）。用 511010 当长债代理会**低估债券腿的利率敏感度**，从而低估其在股灾中的对冲效果——这恰好是全天候最核心的卖点。建议补 `511260`（十年国债ETF）或 `511090`（30年国债ETF）作为长腿，与 511010 并存，让用户自己选。

## 五、版本计划（对方案 §开发顺序 的修订）

方案的三版划分我基本同意，只做两处调整：

**V1（固定权重 + 日历再平衡 + Run 保存/比较）**
- **加入**：成本口径（哪怕只给两档预设）、Benchmark 口径标注、资产有效区间显示
  - 理由：这三个不加，V1 跑出来的数无法解释。成本不是"锦上添花"，它是结论的一部分。
- **不做**：阈值再平衡、归因、滚动指标、风险贡献
- **默认资产池**：先用现有 5 个复权标的 + 指数日线 + 商品 + 转债指数，不等待新数据源

**V2**
阈值再平衡（含 check × trigger 正交设计）、**多 Run 对照归因（零成本口径下为两 Run）**、滚动指标、风险贡献、交易日历跨市场扩展

**V3**
Risk Parity / 估值动态权重 / 趋势过滤 / 风格轮动 —— 统一 `PortfolioStrategy.target_weights(date, context)` 接口

**V4**
个股日线扩容 + 波动做 T 执行研究（注：执行研究的代码其实已就绪，只差标的扩容，边际成本最低，可提前）

## 六、需要你拍板的问题

按阻塞程度排序：

1. **Benchmark 口径**：用 ETF 的 HFQ 序列（推荐，但覆盖面受 `research.yaml` 限制）／继续用指数 PR 序列但强制标注／引入中证全收益指数（需新数据源）。**这是"相对红利超额"这条指标的生死线。**
2. **债券腿代理**：511010（5年，现有）／补 511260 或 511090（10年/30年，更贴近经典全天候）／两个都上让用户选。
3. **V1 是否含成本**：我主张含（至少两档预设）。若你认为第一版就该零成本看"纯资产配置效果"，也请明确——但那时要同步接受"再平衡贡献"这一列不可信。
4. **场外基金**：V1 直接不支持（推荐）／先接净值数据源再开。
5. **标的扩容**：是否现在就把常用 ETF（红利低波 ETF、黄金 ETF、纳指 ETF、30年国债 ETF）加进 `research.yaml` 跑一次全历史抓取。这是**解锁 V1 的前置动作**，且几乎零风险。
6. **数据起点**：V1 默认回测区间建议设为"各资产共同有效区间"，而非让用户填 2015 然后发现数据不够。

## 附：与既有系统的关系

本引擎不应成为新的独立系统，而是把现有模块串起来：

```
index_universe (统一资产注册, 已八成)
        ↓
get_series(asset_id, start, end, return_type)   ← 新增适配层
        │   ├── index_daily_quote
        │   ├── research_daily_bar_adjusted (HFQ)
        │   ├── commodity_daily_price
        │   ├── cb_index_daily
        │   └── (未来) 场外净值 / 债券指数
        ↓
Portfolio Engine (持仓账本 + 再平衡 + 成本)
        ↓
backtest_run (复用 ResearchReplayRun 范式: 参数即身份 + input_hash)
        ↓
Analytics (绩效 / 归因 / 多 Run 对照)
        ↓
/portfolio-lab + /backtest 页面
```

估值、风格、转债、商品这些已有页面继续各自演进；引擎只消费价格序列，不复制它们的逻辑。
