# 次日 T 价位：行情事实层与停用规则设计（2026-09-18）

状态：设计稿，供用户确认；**尚未批准编写策略或页面代码**。

## 1. 目标与边界

从现有高股息股票和可转债正股名单选取 A 股；ETF 可按代码加入关注名单。交易日收盘后，在同日原始日线、复权因子与交易日历齐备时，为下一交易日生成可解释的买卖各三档**建议**、每档数量与 T 仓上限；不连接券商、不创建或取消真实条件单。首版只用日线；日线只能验证某档是否被日内高低价触达，不能推断买卖发生顺序或真实成交利润。

本稿先固定两个实施前提：可替换的行情数据层；可枚举且有精确定义的停用原因。页面与策略代码要在行情层验收后开展。现有 `StockDividendDaily` 只有现价/前收而没有连续 OHLC，`IndexDailyQuote` 属于指数，`CommodityDailyPrice` 属于商品；均不得冒充股票/ETF 日线输入。

## 2. 实施顺序及验收门槛

1. **Phase 0 数据源核验。** 用目标账户实际调取股票 `daily`、`adj_factor`、基金 `fund_daily`、`fund_adj`、`trade_cal`、证券基本信息各一个股票/ETF 样本与至少 220 个交易日。记录返回字段、覆盖、更新时刻、权限、频率和异常响应。未通过时不能把 Tushare 定为唯一生产源，也不能开启 ETF 建议。
2. **Phase 1 行情事实层。** `MarketDataProvider` 协议、Tushare 适配器、证券元数据、交易日历、原始日线、独立复权因子、同步状态与修订记录；增量采集及质量检查。只采集用户关注的标的，不全市场拉取。
3. **Phase 2 连续价格与指标。** 在给定 `as_of` 日和数据修订版本下构建连续 OHLC，计算 EMA20、Wilder ATR14、120 日上下偏移分布与 Z。只产出计算快照；先用固定样例核对时间顺序。
4. **Phase 3 次日计划。** 明确停用原因、价位、数量及开盘失效线；停用时不产生可用六档。
5. **Phase 4 页面。** 展示原始行情日期、计算日期、六档、仓位输入、算法版本和停用原因；无真实下单按钮。
6. **Phase 5 历史验证。** 先统计日线触达率及参数稳定性；若要判断成交先后和 T+1 库存变化，另行接入分钟数据。

Phase 1 的放行条件：目标账户与品种所需接口已验证；连续样本覆盖不少于 220 个交易日；同一交易日原始 OHLC 与因子可对齐；缺数/修订/除权/停牌有可见状态；重跑不重复，源端纠错可追溯。不能以“接口返回 HTTP 200”代替这些检查。

## 3. 行情服务边界

策略、页面、查询 API 不直接导入 Tushare、AkShare 或调用其接口。适配器只返回规范化数据，持久化与校验由服务层负责。

```python
class MarketDataProvider(Protocol):
    def get_daily_bars(self, symbol, start, end) -> list[RawDailyBar]: ...
    def get_adj_factors(self, symbol, start, end) -> list[AdjFactor]: ...
    def get_trade_calendar(self, exchange, start, end) -> list[TradeSession]: ...
    def get_security_info(self, symbol) -> SecurityInfo: ...
```

`symbol` 用带交易所后缀的规范代码（如 `600900.SH`）；名单中的六位代码须经证券主数据解析后才能抓取。Provider 不做 EMA/ATR、仓位分配或条件单决策。V1 的主适配器候选是 Tushare Pro；AkShare/东方财富仅可作为另一个明确来源的核验或后续备援，不混写成同一来源。上游调用必须有超时、限速、退避和任务级截止时刻；缺少当天数据时重试，但不得拿昨天数据生成“明日”计划。

Tushare 文档说明股票 `daily` 有 OHLC、`pre_close`、成交量与金额；其中 `pre_close` 是**除权昨收**，不是可以直接与前一日未复权收盘价混用的字段。股票因子由 `adj_factor` 提供；基金日线由 `fund_daily` 提供，基金因子由 `fund_adj` 提供。官方权限表当前显示 `fund_adj` 至少 5000 积分且约 17:00 更新，因此账户授权必须作为 Phase 0 的真实检查，不能按文档存在即认为可用。来源：[股票 daily](https://tushare.pro/document/2?doc_id=27)、[股票 adj_factor](https://tushare.pro/document/2?doc_id=28)、[基金 fund_daily](https://tushare.pro/document/2?doc_id=127)、[权限与更新时间](https://tushare.pro/document/1?doc_id=108)、[交易日历](https://tushare.pro/document/2?doc_id=26)。

## 4. 表与不可变边界

| 表 | 核心字段与唯一键 | 用途 |
| --- | --- | --- |
| `security_master` | `symbol` 唯一；名称、`asset_type`、`exchange`、`board`、上市/退市日、`price_tick`、`buy_lot`、`sell_lot`、`settlement_type`、来源、更新时间 | 证券身份与交易规则；字段缺失则不能出股数。T+0/T+1 按具体 ETF/证券识别，不能仅凭 `asset_type` 猜测。 |
| `trade_calendar` | (`exchange`, `cal_date`) 唯一；`is_open`、`pretrade_date`、来源、更新时间 | 判断目标交易日及新鲜度；交易日不按自然日推断。 |
| `daily_bar` | (`symbol`, `trade_date`, `source`) 唯一；未复权 `open/high/low/close`、源端 `pre_close`、原始 `volume/amount`、源单位、获取时间、内容哈希、质量状态 | 原始事实层。`pre_close` 保留源字段名与定义，指标不能盲用。 |
| `daily_adj_factor` | (`symbol`, `trade_date`, `source`) 唯一；`factor`、获取时间、内容哈希、质量状态 | 与价格分离保存；缺失、非正、非有限值视为错误。 |
| `market_data_revision` | 记录表名、业务键、旧/新内容哈希、旧/新规范化载荷、`observed_at`、任务运行 ID | 源端补录或纠错时保留旧版本；不能宣称供应商原始数据永远不会修订。 |
| `market_data_sync_state` | (`symbol`, `dataset`) 唯一；最后尝试/成功时间、源最新日期、状态、错误 | 数据状态页与补抓依据。 |

V1 不复制一份永久的前复权 K 线。价格/因子以源端原始口径入库；因数据商可能修正历史，当前值允许幂等更新，但每次**内容变化**必须写修订记录。计划快照保存 `as_of`、数据截止日、算法/参数版本、使用的输入修订标识或完整输入快照哈希、结果与停用原因；需要精确复现旧计划时从修订记录还原对应版本，只有哈希不足以还原。

金额与数量的源端单位须在 Provider 边界明确转换并在表中统一；不得把 Tushare 股票 `vol` 的“手”和 ETF `vol` 的“份”混为同一个无单位数字。数据库迁移沿用现有 Alembic 序列，`init_db()` 的模型注册也须同步，避免新环境与既有库结构漂移。

## 5. 同日数据齐备与复权连续性

交易日 T 的 15:00 仅表示市场收盘，**不表示数据供应商完成入库**。调度器可从收盘后轮询；股票和 ETF 均须验证 T 日 bar、因子、日历及证券主数据齐备，再生成 T+1 计划。因基金因子官方标为约 17:00 更新，建议把生成检查放在 17:30 以后并在有限时窗内补试；实际时刻由 Phase 0 实测决定。截止时仍缺项则停用，不沿用旧计划。若 T 非交易日，以最近已收盘且已核实的交易日为计算日期，目标日由交易日历决定。

每个交易日校验：`0 < low <= min(open, close) <= max(open, close) <= high`、OHLC 有限、交易日属于日历、代码与品种一致、没有重复日期；成交量/金额的可空性按源接口确定。停牌由源端停复牌信息或明确的零交易状态识别；“应有行情却没有”只能记为 `DATA_MISSING`，不能臆断停牌。除权事件优先使用公告/事件或因子跳变识别；源端数据不一致、因子缺失或无法衔接时停用。**发生除权的 T 日即使数据可算，V1 也停用 T+1 计划**；之后连续数据校验通过才恢复。

给定计算截止日 T，把历史第 t 日原始 OHLC 全部换算至 **T 日未复权交易价格尺度**：

```text
adjusted_price(t, T) = raw_price(t) * factor(t) / factor(T)
```

同一根 K 的四价使用同一个比率。此定义与 Tushare 文档所述按指定结束日做前复权一致；不能把源 `pre_close` 与 `raw_close(t-1)` 直接相减。`TR_t = max(H_t-L_t, |H_t-C_(t-1)|, |L_t-C_(t-1)|)` 中所有值均须是同一 T 日尺度的连续价。历史回放必须以各自的 `as_of` 日计算；不能用今天才取得的修订版行情重写过去曾生成的计划。来源：[Tushare 复权公式及 end_date 口径](https://tushare.pro/document/2?doc_id=146)。

## 6. 指标及时间边界（Phase 2 的固定契约）

至少取 200 根有效日线，若预热或完整 120 个历史偏移样本不足，则停用。EMA20 使用收盘价并写死初始化方法；ATR14 使用 Wilder 平滑并写死首个 14 日真实波幅的初始化，算法版本变化须使旧计划可区分。历史交易日 t：

```text
Down_t = max(0, C_(t-1) - L_t) / ATR_(t-1)
Up_t   = max(0, H_t - C_(t-1)) / ATR_(t-1)
```

前收、当日高低与 ATR 均使用相同复权尺度，且 `ATR_(t-1)` 只能使用 t-1 以前数据。`max(0, …)` 把整日未越过前收的侧向偏移记为 0，明确参与经验分位。T 日收盘后可把 T 日偏移纳入最后 120 个交易日样本，采用固定的线性插值经验分位方法取上下侧 P50/P70/P85；分位表示偏移**距离**，不是各档命中概率。计算 `Z_T=(C_T-EMA20_T)/ATR_T`，ATR 不正或非有限则停用。收盘后生成建议的任何输入日期不得大于 T。

V1 候选价位公式（Phase 3 才实现）：`Zc=clip(Z,-1.5,1.5)`；买距离 `max(0.2, Q_down_i + λZc)`，卖距离 `max(0.2, Q_up_i - λZc)`，默认 `λ=0.2` 且作为有版本参数；对应未取整价格分别为 `C_T-ATR_T*距离`、`C_T+ATR_T*距离`。先通过停用过滤，再按证券元数据 tick 取整、去除重复或越界档位；不能把无效档填成看似可挂的价格。该默认值只用于首版历史验证，不代表已验证收益。

## 7. 停用原因（Phase 1 提供检测事实，Phase 3 做决定）

同一计划允许多个 `reason_code`，记录触发数值、阈值、相关交易日和证据来源。任何停用原因出现，输出 `DISABLED` 与原因，不输出“可用六档”；旧计划不可跨交易日沿用。

| reason_code | V1 精确定义 |
| --- | --- |
| `DATA_MISSING` | 交易日历标记为开市，但 T 日必需的 OHLC/因子未在截止时齐备；或最近 120 个样本中出现无法解释的日期/字段缺口。 |
| `ADJ_FACTOR_ERROR` | 任一必需因子缺失、非正、非有限；同日存在相互矛盾的因子；价格/因子换算后出现无法解释的断层。 |
| `CORPORATE_ACTION` | T 日存在经核实的除权除息/送转事件，或相邻交易日因子变化且事件尚未核实；V1 当天一律停用下一日计划。 |
| `INSUFFICIENT_HISTORY` | 有效日线少于 200 根，或 EMA/ATR 预热后未形成完整的 120 个偏移样本。 |
| `SUSPENDED` | T 日有明确停牌/暂停交易事实；仅“无日线”不判为停牌。 |
| `EXTREME_Z` | `abs(Z_T) > 1.5`。等于 1.5 不触发；先检查 ATR 有效性。 |
| `VOLATILITY_SPIKE` | `ATR14_T/C_T > 2.0 × median(ATR14_t/C_t, t∈最近60个有效交易日且 t<T)`；中位数必须为正且样本齐备。2.0 为初始保险丝，需历史回放验证。 |
| `TRADING_RULE_UNKNOWN` | `price_tick`、买卖数量单位、结算属性或板块规则无法从证券主数据确认。 |

`TREND_BREAK` 暂不在 V1 启用：仅有名字而没有经核对的公式会造成不可解释的停用。若后续增加 EMA 斜率、通道突破等，须给出计算窗口、阈值、边界测试并升级算法版本。`EXTREME_Z` 和 `VOLATILITY_SPIKE` 是明确的首版保险丝，不能宣称已经实证优化。

## 8. 隔夜跳空、仓位和交易规则

收盘后建议另显示**次日开盘失效线**：开盘低于 `C_T - 1.5*ATR_T` 时买侧计划失效；开盘高于 `C_T + 1.5*ATR_T` 时卖侧计划失效。此为次日开盘才知道的条件，不能写成“收盘生成时已判定”。首版没有盘中行情与券商连接，页面只能提示用户次日检查，**不保证已经挂出的券商条件单会自动取消**；文案不得暗示无人值守安全执行。若用户以后要求前夜直接挂单并自动取消，需先验证券商是否支持开盘价过滤、复合条件与触发后限价，否则不进入自动化范围。

数量建议基于手动录入的总持仓、可卖持仓、可用资金、T 仓上限；买侧三档合计金额不超过 `min(可用资金,T仓上限)`，卖侧三档合计数量不超过 `min(可卖持仓, 按T仓上限/基准价折算的数量)`。各档先按 1/3 分配，再按证券元数据的数量单位向下取整；不足一档最小单位则该档标为不可用，不借用未来卖出回款给买侧。普通 A 股/基金的 tick 与买入单位有现行交易所规则，但部分板块/ETF 规则不同，必须逐证券落库并核对，不能用 `if ETF else STOCK` 猜测。[上交所交易规则](https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/exchange/c/c_20260424_10816482.shtml)、[深交所交易规则](https://docs.static.szse.cn/www/lawrules/rule/trade/W020260424690713155663.pdf)。

## 9. 验证清单与未完成的外部前提

- [ ] 账户实测股票/ETF 日线、因子、日历、主数据接口，记录权限及盘后实际可用时间；ETF 因子权限不足时首版 ETF 保持停用。
- [ ] 同一 T 日 raw bar + 因子齐备才发布可计算状态，缺失、停牌、除权分别得到不同代码。
- [ ] 复权事件日前后构造样例，验证历史价与 T 日价同尺度；源 `pre_close` 不直接参与指标。
- [ ] 历史 t 的分母确为 `ATR_(t-1)`；T 日只进入 T 收盘后形成的下一日计划。
- [ ] 源端回写同一业务键时产生修订，旧计划仍可按原输入重放。
- [ ] 120 个完整样本、Z 与波动保险丝的等号边界、价格/数量取整与无可用档位情况均有固定样例。
- [ ] 收盘后任务截止仍缺数据时明确停用，不把上个交易日计划显示为明日计划。
- [ ] 跳空失效线展示为**次日人工检查条件**，没有自动取消的暗示。

Phase 0 的 Tushare 凭据、实际权限、ETF 类型/结算属性来源尚未验证；这是开始行情层编码前的外部前提，不用臆测值填补。除这些需真实账户核验的事项，本稿定义了首版时间边界、存储契约和停用规则。
