# 转债市场概览：系统设计与实施方案

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为内部团队提供可信的转债市场日频概览，支持查看最新状态、定位历史日期、进入选债流程。

**Architecture:** 沿用现有转债指数抓取、存储与查询接口；修复位置解析风险，前端以专用数据转换模块和共享时间轴图表呈现。市场统计与个债筛选分开维护口径，不新增数据库表、数据源或通用指标平台。

**Tech Stack:** Vue 3、Vue Router、ECharts、Vitest、FastAPI、SQLAlchemy、pytest。

日期：2026-09-10。代码核对基线：`ebc810f`。原需求：`docs/requirements-cb-market.md`。本文是替代性设计与实施交接文件，保留原稿便于对照；本轮只交付方案，未开发、部署或实测生产数据。文中路径相对 `D:\gitub_codes\web`。

## 1. 先给结论

原需求**部分达标**：两个核心字段已存在，但“把日报图搬到网页”的描述没有完整覆盖数据可信度、日常操作和验收。应做一个小而完整的市场概览，而非继续扩充一张图。

本方案作出以下裁决：

| 原稿内容 | 裁决 | 最终设计 |
|---|---|---|
| 独立 `/cb-market` 页面 | 保留 | 名称改为“转债市场”，作为可转债导航组首项 |
| 双轴叠加图 | 修改 | 上下两幅走势，共享日期轴、游标与缩放，各自明确单位 |
| 默认全历史，提供10年 | 修改 | 默认3年，提供1年／3年／5年／全部；不提供当前几乎与全部重复的10年 |
| 最新摘要放在图下 | 修改 | 放在图上，展示同一数据日期的三个核心数值 |
| 展示成交额、温度 | 本期删除 | 成交额不在现有接口；温度缺乏可交付的计算定义 |
| 后端无改动 | 修改 | 业务接口结构保持；补日期位置解析修复与契约测试 |
| 按图形范围、线上比本地新验收 | 删除 | 按同日字段数值、状态行为、部署版本和同步记录验收 |
| 预留更多指标 | 收敛 | 代码按职责拆分即可；不做动态指标注册或隐藏功能入口 |

这是本次方案的推荐设计，不表示以前待确认的筛选合并、模板重命名和行业列已获得实施授权。

## 2. 需求审查：具体缺口

以下先列反例，不以作者解释代替代码证据。

1. **成交额无法用现有数据契约交付。** 原稿 `docs/requirements-cb-market.md:21` 要求成交额，`:27` 又限定直接复用接口且后端不改。`backend/api/routes/cb_index.py:34` 起的返回字段没有成交额；`turnover_rate` 是换手率，不能换标题冒充成交额。旧项目 `D:\gitub_codes\market-daily\src\convertible\screening\render.py:46` 的摘要读取另一对象中的 `volume`，不证明当前历史接口有该字段。
2. **历史平均收益率易与个债自定义收益率混同。** 原稿 `:19`、`:21` 未说明口径。`backend/services/fetchers/cb_index.py:40` 将源字段 `avg_ytm_rt` 原样映射为 `avg_ytm`；`backend/services/cb_intraday.py:12` 定义的是自定义非年化收益率。不能把两者称为相同指标，也不能用当前个债快照重算多年市场历史。
3. **验收不能依赖价格永远在95–145或收益率约−10%。** 原稿 `:48` 的范围会随时间变化；双轴范围也能改变视觉形状。正确性应由同日数据验证，不能由“看起来像日报”判定。
4. **“线上比本地新”不是合格标准。** 原稿 `:50` 在同日已同步、休市或本地刚拉取时无法成立。应该比较预期数据日期、已部署版本和同步状态，并承认来源发布延迟。
5. **数据数组存在错位反例。** `backend/services/fetchers/cb_index.py:84` 的解析表达式过滤空元素：日期 `[d1,d2,d3]`、数值 `[100,,102]` 会变成 `[100,102]`，使102落在d2。先修解析，图表才有可信的日期基础。这是代码可构造的反例，不声称已发现生产库污染。

原稿 `:26` 的2106行、起止日期和约200KB是待验证的环境快照，不纳入设计常量。本轮未查询生产库，也未访问指定日期的日报成品；已核对旧项目画图代码作为参考。

## 3. 产品定位与方案选择

### 3.1 用户要完成的事情

典型用户是每天查看一次市场的内部同事。他需要快速知道：当前价格中位数是多少、来源平均到期收益率是多少、这些值属于哪一天；随后查看近几年变化，必要时进入转债筛选。页面不产生买卖信号，不把价格中位数直接解释成收益、估值分位或投资建议。

操作链路：**打开页面 → 核对数据日期和最新三项 → 选择时间范围／定位某天 → 进入转债筛选**。历史游标只改变图上的历史读数，不能悄悄把顶部最新摘要改成历史数据。

### 3.2 三种路径比较

| 路径 | 开发代价 | 用户和维护影响 | 决定 |
|---|---|---|---|
| 原样搬双轴图 | 最低 | 容易比较两条线的交叉和斜率，却忽略不同轴；摘要口径仍需修正 | 不采用 |
| 独立市场概览＋共享时间轴双图 | 低至中 | 价格和收益率分开读、同日对照；不干扰选债条件 | **采用** |
| 与筛选、因子合并为完整工作台 | 高 | 涉及模板、口径、导航和状态迁移，扩大本需求 | 本期不做 |

选择双图是信息表达决定，不只是布局偏好。不再增加“切换双轴模式”的第二套实现。保留日报同日期的数值可比性，不追求像素或线形比例一致。

## 4. 页面设计与交互契约

### 4.1 页面顺序

1. 标题“转债市场”，副标题“日频市场统计”；右侧“转债筛选”链接到 `/cb-list`。
2. 数据说明：“数据截至 YYYY-MM-DD · 来源：集思录转债指数历史”；刷新按钮只重新请求本系统API，不触发抓取任务。
3. 最新摘要：价格中位数（元）、平均到期收益率（集思录口径，%）、转债数量（只）。三个值严格取同一最新合法日期的记录；缺失显示 `—`，不从其他日期补值。
4. 时间按钮：1年、3年、5年、全部；默认3年。下面显示实际区间和记录数。
5. 上图“价格中位数（元）”，下图“平均到期收益率（集思录口径，%）”，底部共用缩放条。
6. “当前查看 YYYY-MM-DD：价格中位数 …；平均到期收益率 …”文本行，支持点击／触摸图表后固定读数；左右日期按钮按实际记录逐日移动，便于手机和键盘使用。
7. 可展开“数据口径”说明及“查看数据状态”链接 `/status`。

桌面图表合计约480px高，手机约420px；375px宽度下摘要可分行、时间按钮允许换行，整页不产生横向滚动。数值读数始终可在图外文本行读取，不只依赖 hover。

### 4.2 图表规则

- 一个 ECharts 实例、两个 grid／xAxis／yAxis、两条 line series；两个日期轴用同一排序后的记录数组。
- 价格蓝色实线、收益率橙色虚线；每幅图有标题与单位，颜色不是唯一识别方式。
- `dataZoom.xAxisIndex=[0,1]`，`axisPointer.link=[{xAxisIndex:[0,1]}]`；两个图的窗口和指示日期同步。
- `smooth=false`、`connectNulls=false`，不补0、不插值；一条线缺值时另一条仍保留该日数据。整个日期不存在时不补日历数据，不推测休市或源缺报。
- y轴自适应数据，不固定95–145，不强制收益率为正；单一数值也要有可见范围，只有一个点时显示点标记。
- 切换1／3／5年或全部后，缩放重置为该窗口完整区间，日期读数重置到窗口最后一条记录；刷新同样重置，避免旧缩放遮蔽新数据。
- 图例仅识别，不提供隐藏序列功能；本期不加均线、分位参考线、买卖区间和额外指标。

### 4.3 时间定义

窗口锚点是**接口中最新合法日期**，不是浏览器今天；显示截至日期即可暴露陈旧数据。按自然年减1／3／5年，2月29日回落到目标年的2月末，边界包含起止两天。全部使用 `YYYY-MM-DD` 的日历语义，不因时区解析变成前一天。

若全部历史不足所选年数，显示“历史不足3年，展示已有记录”，不伪造缺失历史；若窗口存在记录但两项核心指标均为空，显示“该区间暂无有效指标”，保留时间按钮。

### 4.4 失败与数据新鲜度

| 状态 | 页面行为 |
|---|---|
| 首次加载 | 摘要和图表骨架，禁止重复刷新 |
| 首次请求失败 | 明确失败提示和重试，不显示0值图 |
| 返回空数组 | “暂无转债市场历史数据”，提供数据状态入口 |
| 部分字段缺失 | 缺项为 `—`，其余可读；显示缺失说明 |
| 刷新失败且已有数据 | 保留上次成功结果、截至日期，提示刷新失败，不伪装新数据 |
| 日期错误／重复日期 | 非法日期丢弃并计数；重复日期的整组记录都不绘图，显示数据异常提示，避免任取一条 |
| 数据较旧 | 截至日期始终可见；超过7个自然日附中性提示“已超过7天无新记录，节假日或同步延迟均可能导致” |

本期不引入前端交易日历，不将“距今天数”直接判为同步故障，也不写“已实时更新”。数据日期不是抓取完成时间。

## 5. 数据口径与接口契约

沿用 `GET /api/cb-index/daily`，数组返回，后端当前按日期降序，前端防御性规范化为升序。新增 API client：

```js
export const getCbIndexDaily = () =>
  api.get('/cb-index/daily').then((r) => r.data);
```

| 字段 | 含义／展示 | 无效处理 |
|---|---|---|
| trade_date | 数据所属日期 | 必须为真实ISO日期，否则丢弃整行 |
| median_price | 来源价格中位数，元 | null／非有限数／非正数显示缺失 |
| avg_ytm | 来源 avg_ytm_rt，百分数值 | null／非有限数显示缺失；允许0和负数，不再乘100 |
| count | 来源转债数量，只 | 仅接受非负整数，异常值缺失，不四舍五入 |

实际源样本范围、剔除规则和收益率算法未由本地代码完整定义。口径说明明确“按来源统计值展示，非本系统自定义选债收益率”；不得声称是本系统全部在市转债重算平均，也不能承诺完整覆盖所有转债。

固定示例：`{"trade_date":"2026-09-09","median_price":132.5,"avg_ytm":-8.25,"count":400}` 应显示132.50元、−8.25%、400只。示例仅为测试夹具，不是当日真实市场值。

**最新摘要规则：** 在规范化且去掉重复组的数据中，取最大日期记录，即使其核心字段缺失也不回退到旧日冒充最新。图表同时显示各指标最后有效日期；日期不同即分别标注。

**缓存与负载：** 一次进入页面请求一次全量，按钮切换全部本地完成；手动刷新再请求。不轮询、不持久化浏览器历史数据。本期保留全量接口；发布时记录实际响应字节数和时延，不能沿用“200KB”估算作为实测结果。若目标环境实测超过1MB或图表就绪超过3秒，先记录瓶颈并阻止性能验收通过，再决定压缩、后端区间查询，不能顺手引入分页导致全历史缺段。

## 9. 发布、回滚与后续边界

前后端查询契约不变，可独立发布；解析修复需要先过反例测试。新增页面按路由懒加载，不把历史请求放进全局布局。

回滚UI只撤销新增入口与页面发布；正常数据无需回滚。若解析修复发现新源格式不兼容，保留既有历史并将抓取失败显式暴露，不能退回已知会错位的解析逻辑继续写库。需要历史修复时单独备份、对照、记录处理日期范围，不清空整个数据库。

后续只有出现明确使用需求才扩展：成交额需独立核对数据源、时间和单位；温度需先定义公式与含义；更多指标需按用户任务选择；选债工作台合并仍遵循原待确认项。当前独立概览页面与数据函数可保留，无需先重构全部转债模块。
