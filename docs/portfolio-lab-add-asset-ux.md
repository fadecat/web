## 〇、先看三个刚核实的事实（它们直接决定交互形态）

### 事实 1 · 六位数字**三义冲突**——这条决定"必须让用户指明类型"

实测同一个 `000001`：

| 输入             | 命中         | 类型   |
| -------------- | ---------- | ---- |
| `sz000001`（腾讯） | **平安银行**   | 股票   |
| `000001`（蛋卷）   | **华夏成长混合** | 场外基金 |
| `sh000001`（腾讯） | **上证指数**   | 指数   |

**三个不同的东西，同一个 6 位数字。** 这不是边角案例——`000001` 是国内最常见的示例代码。

→ 所以"输入框 + 自动识别"**不能只有自动**，必须有让用户指定类型的能力。

### 事实 2 · 两个源都能即时回名称——所以"预览确认"这一步几乎零成本

| 源                       | 覆盖                | 返回的关键字段（实测）                                             |
| ----------------------- | ----------------- | ------------------------------------------------------- |
| 腾讯 `fqkline`            | 股票 / ETF / **指数** | `qt[1]` = 名称（长江电力 / 平安银行 / 纳指ETF国泰 / 创业板ETF易方达 / 沪深300） |
| 蛋卷 `/djapi/fund/{code}` | 场外基金              | `fd_name` / `type_desc` / `manager_name` / `found_date` |

→ 用户输完代码就能看到"是不是这只"，**不用猜、不用等抓取**。

（注意：蛋卷的**详情接口对场内 ETF 不可用**——`513100` 返回 `600001 该基金暂不销售`；但它的**净值接口可用**。所以场内标的的信息一律走腾讯。）

### 事实 3 · 首次抓取是有成本的——所以要异步 + 状态

| 源                | 单页上限        | 一只 20 年标的的全历史 |
| ---------------- | ----------- | ------------- |
| 腾讯 `fqkline`     | **640 条/页** | ≈ 8 页         |
| 蛋卷 `nav/history` | 6000        | **1 个请求**     |

→ 添加后不能"转圈等"，要立刻进列表并显示状态。

## 一、入口：查看态 / 编辑态两个态

| 态       | 内容                                   | 说明   |
| ------- | ------------------------------------ | ---- |
| **查看态** | 完全复刻韭圈儿（收益条 / 曲线 / 相关性 / 详情表），**只读** | 默认进入 |
| **编辑态** | 增删标的、设权重、设添加日、选再平衡与区间                | 我方增强 |

入口：**组合详情页（L2）** 右上角 **`编辑组合`** 按钮 → 切换/打开抽屉编辑器。

> ⚠ **与 L1 列表页的区分**（勿混）：
>
> - **L1 组合列表**的入口是 `创建组合` / 卡片级 `复制` —— 那是"**组合级**"操作（新建、复制整个组合）。
> - **L2 组合详情**的入口是 `编辑组合` —— 那是"**成员级**"操作（增删标的、改权重）。
> - 两者不是一回事：L1 管"有几个组合"，L2 管"这个组合里有什么"。详见 `portfolio-lab-page-spec.md` §九 与 `portfolio-lab-multi-portfolio.md` 〇之二。

**为什么分两态**：韭圈儿的组合详情是"看结果"的页面，添加动作在另一个页面。我们要复刻它的清爽，又必须加"自由添加"，最自然的分法就是两态。

## 二、添加流程（5 步）

### 第 1 步 · 打开添加框

```
┌───────────────────────────────────────────────┐
│  添加标的                                      │
│                                               │
│  类型  ( 自动 )  股票   ETF   场外基金          │
│                                               │
│  代码  [                                  ]   │
│                                               │
│        支持：600900 / sh600900 / 600900.SH     │
│        （场外基金）支持名称搜索                 │
└───────────────────────────────────────────────┘
```

### 第 2 步 · 输入 → 即时解析（resolve）

**唯一命中** → 直接出确认卡（见第 3 步）。  
**多个命中** → 出候选列表让用户选：

```
┌───────────────────────────────────────────────┐
│  输入 000001 命中 3 个，请选择：                │
│                                               │
│  ○ 平安银行          股票 · 深市 · 腾讯         │
│    1991-04-03 ~ 2026-09-18                    │
│  ○ 华夏成长混合       场外基金 · 蛋卷            │
│    2001-12-18 ~ 2026-09-18                    │
│  ○ 上证指数          指数 · 沪市 · 腾讯         │
│    1990-12-19 ~ 2026-09-18                    │
└───────────────────────────────────────────────┘
```

**无命中** → 明确说"未找到"，并给出可能原因（代码错 / 该源不覆盖 / 指数代码口径不同）。

### 第 3 步 · 确认卡（关键：把口径摆在用户面前）

```
┌───────────────────────────────────────────────┐
│  易方达黄金主题人民币A          场外基金         │
│  161116 · QDII-商品 · 殷春涛                   │
│                                               │
│  可用数据区间   2011-05-09 ~ 2026-09-17        │
│                 (3602 个交易日)                │
│  复权口径       分红再投净值 (NAV_ADJ)          │
│  数据源         蛋卷                           │
│                                               │
│              [ 取消 ]      [ 添加 ]            │
└───────────────────────────────────────────────┘
```

**复权口径必须显示**——三类资产的口径不同（股票/ETF = `HFQ` 后复权；场外基金 = `NAV_ADJ` 分红再投；指数 = `PRICE` 价格）。这是之前设计里定的 `price_basis`，在添加环节就要让用户看见。

### 第 4 步 · 加入列表

回到编辑器列表，**新行立刻出现**（状态：同步中），权重**默认留空**（列表底部提示"权重合计 100% 才能回测"）。

```
标的                        类型    初始比例   状态
大成中证红利指数A 090010     场外     25.00%    就绪
富国天利增长债券A 100018     场外     25.00%    就绪
纳指ETF国泰 513100          ETF      25.00%    就绪
易方达黄金主题A 161116       场外       —       同步中 ▁▃▅
                                    [+ 添加标的]
```

### 第 5 步 · 抓取完成 + **组合起点变化提示**（最重要的一条）

> ⚠️ **这可能是整个交互里最容易被忽略、但影响最大的一步。**

组合的可回测起点 = 所有标的"数据可得区间"的共同起点（= 最晚那个）。**加一个新标的，可能把整个组合的起点往后推**。

```
⚠ 新的组合起点：2013-04-26
   （受 纳指ETF国泰 513100 制约，其数据始于 2013-04-26）
   原起点 2003-12-02 → 前移 9.4 年
   [ 知道了 ]   [ 移除该标的 ]
```

**不提示的后果**：用户加了只 2021 年成立的 ETF，发现"近10年"没了，却不知道为什么。

## 三、五个关键交互细节（我建议的做法）

| #   | 细节                  | 建议                                                            | 理由                                                                   |
| --- | ------------------- | ------------------------------------------------------------- | -------------------------------------------------------------------- |
| 3.1 | **代码归一化**           | 接受 `600900` / `sh600900` / `600900.SH` / `SH600900` 四种写法，内部统一 | 用户不该记格式。推断规则：`6/5/9` 开头 → sh，`0/1/2/3` → sz（北交所 `4/8` 开头暂不支持，见 §6-⑤） |
| 3.2 | **类型默认"自动"，冲突时列候选** | 不做"强制先选类型"（多一步），也不做"纯自动"（会猜错）                                 | 事实 1 说明"纯自动"不可行；"先选类型"对熟练用户是负担。折中：默认自动 + 一键切换 chip                   |
| 3.3 | **权重在添加后统一设**       | 添加时**不填权重**，列表里统一编辑                                           | 避免"加第 4 个标的时不知道前三个占多少"的来回算                                           |
| 3.4 | **首次抓取异步 + 状态回显**   | `同步中 → 就绪 / 失败`，失败可重试；**不阻塞其他操作**                             | 腾讯 8 页要几秒                                                            |
| 3.5 | **起点变化即时提示**        | 见第 5 步的警示条                                                    | 见上                                                                   |

## 四、异常与边界（8 种）

| 场景              | 处理                                               |
| --------------- | ------------------------------------------------ |
| **重复添加**（已在组合里） | 幂等：直接提示"已在组合中"，不重复抓取                             |
| 代码无效            | "未找到该代码"，并提示可能原因                                 |
| **抓取失败**        | 该行标红 + `重试` 按钮；**不阻塞其他标的**，也不影响已就绪的标的使用          |
| **数据太旧/疑似退市**   | 规则（歧义审计 D9）：若最新数据日 < 组合末端 − 5 个交易日 → **拒绝添加**并说明 |
| 组合只有 1 个标的      | 允许（组合退化为单资产；相关性区隐藏）                              |
| **名称搜索无 token** | 降级为"请输入代码"。搜索是输入辅助，**不进关键路径**（token 失效不影响添加）     |
| 网络/源不可达         | 明确报错 + 可重试；不吞异常                                  |
| 权重合计 ≠ 100%     | 列表底部常驻提示，`组合回测` 按钮置灰                             |

## 七、本轮顺带核实 / 纠正的三件事（附证据）

### ① ✅ 关闭长期未核对项：沪深300 基准 39.17%

用腾讯 `sh000300` 分页取 2560 行（4 个请求），2016-09-14 ~ 2026-09-18：

```
2016-09-14 close=3238.73  ->  2026-09-18 close=4507.39
价格指数区间收益 = 39.17%     [韭圈儿页面显示 39.17%]   ✓ 完全一致
```

### ② ⭐ 实证：韭圈儿的基准是**价格指数（不含股息）**

上面这条同时回答了一个悬了很久的问题——**39.17% 与"价格指数"完全吻合**，说明它没有用全收益。

**方向性影响（重要）**：沪深300 价格指数 11 年约 3.0%/年，而含股息的全收益约 5.5~6%/年（11 年差 ≈ 40pp）。**用价格指数当基准，"组合跑赢沪深300"的画面是系统性偏乐观的。**

→ 落地要求：基准可选（你已裁决），**但必须在图例/tooltip 标注该基准是否含股息**，否则这个对比会误导决策。

### ③ ⚠ 纠正我此前的两个判断

| 此前说法              | 实测                                                                                                           |
| ----------------- | ------------------------------------------------------------------------------------------------------------ |
| ~~"腾讯不提供指数 K 线"~~ | ❌ **错**。`sh000300` / `sh000001` / `sh000922`（中证红利）/ `sz399321`（国证红利）**都能取**。之前失败的真实原因是 **`count` 传 3000 超限** |
| —                 | 🆕 **新坑**：`count > 640` 时接口**静默返回空数组**（`code=0` 不报错）→ 抓取器必须**校验返回行数**，并用 640 游标分页（实测 4 个请求取 2560 行）          |

**红利类指数可用性**（对"基准可选"直接相关）：

| 代码         | 名称         | 腾讯                      |
| ---------- | ---------- | ----------------------- |
| `sh000922` | 中证红利       | ✅                       |
| `sh000015` | 红利指数（上证红利） | ✅                       |
