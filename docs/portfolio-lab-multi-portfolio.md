# 组合实验室 · 多组合支持：复杂度评估与设计

- 日期：2026-09-19
- 起因：需求确认为"**支持多组合**"（用户可创建多个组合）；同日下午用户补充"平衡/不平衡/季平衡/年平衡 属于某个组合**内部的特性**"
- 结论：**支持多组合（列表 + 详情两级）；"平衡方式"是组合内部特性，落库归 `backtest_run`**
- ⚠ 本文件记录**评估过程**，最终结论以 **〇之二** 为准（含一处更正记录，见 0.2.5）

---

## 〇、一句话结论

> **多组合本身几乎不增加成本（引擎 +0、表 +0）；真正的风险是"现在不按多组合建模型，以后重构"。**
>
> 而这一轮核对发现：现有表设计把**再平衡规则 / 基准 / 区间**放在 `portfolio` 上——**这会让"对照"必须靠复制组合**。这是必须现在改对的地方。
>
> **2026-09-19 下午定稿**：**支持多组合**（用户可创建多个）；"**平衡/不平衡/季/年**"是**组合内部特性**（页面上一个切换，落库归 `backtest_run`）。详见 〇之二。

---

## 〇之二、用户裁决（2026-09-19）：**支持多组合**；"平衡方式"是**组合内部特性**

> 用户原话（三轮，逐步收敛）：
> 1. 「多组合 → 单组合。平衡/不平衡/季平衡/年平衡 这些属于**某个组合内部的特性**，这样是不是简单？」
> 2. 「从用户层面出发，用户新建一个组合，组合内各个标的，在这个组合内，去调整平衡的状态，就好了。」
> 3. 「用户选择**组合回测** → **创建组合** → **选择标的** → 跟韭圈一样了。**用户可以创建多个组合**。」

> ⚠ **本文档的更正记录（重要）**
> 第 1 轮我把"多组合 → 单组合"读成了"只做一个组合"，并在第 2 轮进一步收紧到"连组合切换下拉都不做"——**这是错的**。
> 第 3 轮澄清后确认：**"多组合 → 单组合"指的是页面层级（列表 → 详情），不是数量收敛。用户要能创建多个组合。**
> 本节的正确结论如下，此前两轮的表述已作废（保留 0.2.5 作对照，避免重犯）。

| 层 | 问题 | 结论 |
| --- | --- | --- |
| **功能范围** | 用户能创建几个组合？ | **多个**（组合列表 + 组合详情 两级页面） |
| **平衡方式的归属** | 组合字段，还是 Run 参数？ | **是"组合内部特性"没错**（本轮判断正确，保留），**落库时属于 Run**（见 0.2.2） |
| **表结构** | 支不支持多组合？ | **支持**（`portfolio` + `portfolio_id` 外键） |

### 0.2.0 用户视角的完整流程（两级页面）

**用户路径**：`组合回测` → 组合列表 → 新建组合 → 添加标的 → 调平衡状态 → 看结果

| 层级 | 页面 | 用户能做的事 |
| --- | --- | --- |
| **L1 · 组合列表** | 我的组合 | 看/新建/进入/复制/改名/删除组合 |
| **L2 · 组合详情** | 单个组合（复刻韭圈儿） | ① 加/删标的、改权重 ② **调平衡状态** ③ 选区间 ④ 看结果 |

**L2 内部的动作，就是用户第 2 轮说的那三件**：

| # | 动作 | 界面元素 | 看到的结果 |
| --- | --- | --- | --- |
| 1 | 添加标的 | 标的列表 + "添加"（输代码或名称） | 多一行（名称 / 权重 / 添加后收益 / 当前占比） |
| 2 | **调平衡状态** | **一个切换**（不平衡 · 季平衡 · 年平衡） | 结果区刷新 |
| 3 | 选区间 | 区间按钮组 / 自定义 | 结果区刷新 |

### 0.2.1 结论一：平衡方式是**组合内部特性**——它不是"另一个组合"

这是用户三轮里唯一始终不变的判断，**完全正确**：

> **同一组持仓，换个再平衡方式，不算另一个组合。**

韭圈儿的选择与此一致：同一个组合页面上三个 tab 切。所以"组合"= **一组持仓**；"平衡方式 / 区间 / 基准"= **看它的角度**。

**反例（错法）**：若把平衡方式写进 `portfolio`，则"四资产等权 × 3 种平衡 × 3 个区间"要建 **9 个组合**，组合列表全是复制品，而且页面上的 tab 切换**做不了**（切它等于改组合定义）。见 §一。

### 0.2.2 结论二：平衡方式落库归 `backtest_run`

"组合内部特性"落地时还有个精度问题：是 `portfolio` 上的一个**字段**，还是**看这个组合的一个维度**？

| | 方案 A' · 存 `portfolio.default_rebalance` | 方案 B' · 记在 `backtest_run` |
| --- | --- | --- |
| 页面 UX | 一个切换按钮 | **完全一样**，也是一个切换按钮 |
| 切换后能否回头对比 | ❌ 只能"改成季平衡"，看不到不平衡的结果了 | ✅ 每次点回测生成一个 Run，三个并排比 |
| 韭圈儿那种 tabs | 勉强（每次切换要重算，且不留痕） | ✅ 天然支持 |
| Run 幂等 / 留痕 | 无 | ✅ 参数即身份 |

> **UX 相同，差别只在"要不要留痕"**。韭圈儿三个 tab 并列、加上我们已定的 Run 范式都指向 **B'**。
>
> **实现取折中**：`portfolio` 存 `default_rebalance`（**仅用于新建 Run 时预填**），真正的事实来源是那次 Run 的参数。这样"内部特性"的语义满足了，同时保留"三种再平衡并排对比"这个韭圈儿核心功能。

### 0.2.3 结论三：`backtest_run` 存**组合快照**，所以历史是双保险

```
组合列表  ──→  portfolio / portfolio_asset      ← 当前配置（可被编辑覆盖）
Run 历史  ──→  backtest_run（含组合快照）        ← 跑过的那一版配置与结果
```

- **改了组合，不影响旧 Run**：`backtest_run` 记录的是**跑那一次时的成员 + 权重 + 参数**，旧结果始终可复现。
- 所以"多组合"与"组合内反复改"都不丢研究痕迹。
- ⚠ 二期做**跨组合对照**时的注意点：不同组合的**共同起点不同**（受各自最晚标的制约）→ 对比需"**对齐到交集区间**"开关，且明确标注。

### 0.2.4 落地范围（定稿）

```
L1  /portfolio-lab               组合列表（管"组合"）
L2  /portfolio-lab/{id}          组合详情（复刻韭圈儿，管"标的与回测"）

L1 列表内容   组合名 · 标的数 · 可用区间 · 最近一次回测的收益/回撤 · 更新时间
L1 操作       新建 / 进入 / 复制现有 / 改名 / 删除(软删归档)
L2 内容       ① 组合名  ② 标的表（增删改权重）  ③ 平衡切换 + 区间  ④ 结果区

表            portfolio / portfolio_asset / backtest_run / backtest_metrics / fund_nav_daily
新增端点      GET|POST /portfolios、PATCH|DELETE /portfolios/{id}、POST /portfolios/{id}/duplicate
不做          分组/标签/搜索（组合数 >10 再说）；跨组合对比（二期，模型已支持）
```

> ⭐ **"复制现有"建议一期就做**：多组合下它是高频操作（"我想试试把债换成债+金"），成本仅是复制成员行。

### 0.2.5 作废记录：此前两轮的错误结论（保留对照，避免重犯）

| 错误表述 | 为什么错 |
| --- | --- |
| ~~"一期只做单组合，不做列表页"~~ | 用户明确"**可以创建多个组合**" |
| ~~"连组合切换下拉都不需要"~~ | 我从"用户新建**一个**组合"过度推断成"只有一个组合"。实际是**每个组合内**的动作描述，不是数量上限 |
| ~~"单组合唯一损失是无法比较不同持仓"~~ | 前提错误。多组合下这不成立 |

**教训**：用户的"单组合"是在描述**页面层级**（从列表进入单个组合），我在描述**数量**。听到"单 / 多"这类量词时，要先确认它修饰的是**层级**还是**数量**。

## 一、⚠️ 必须先修正的建模问题：什么属于"组合"，什么属于"一次回测"

### 1.1 争的是什么

现有设计（`portfolio-lab-flow.md`）把 **再平衡规则 / 基准 / 区间** 写进了 `portfolio` 表。争点就一句：

> **这三项，是"这个组合的属性"，还是"看它的一个角度"？**

### 1.2 摆一个具体需求

「四资产等权」这一组持仓，我想看 **3 种再平衡 × 3 个区间 = 9 种结果**。

| | 方案 A · 归组合 | 方案 B · 归一次回测 |
| --- | --- | --- |
| 数据模型 | `portfolio` 存 再平衡/基准/区间 | `backtest_run` 存 再平衡/基准/区间 |
| **要建几个组合** | **9 个**（持仓完全一样，只是口径不同） | **1 个** |
| 页面上的「不平衡/季平衡/年平衡」切换 | **做不了**——切它等于改组合定义，得弹"是否保存" | 就是切换 Run，与韭圈儿一致 |
| 改一次权重 | 9 个组合各改一遍（或加同步逻辑） | 只改一处，所有 Run 按新权重重算 |
| 组合列表长什么样 | `四资产等权-不平衡-近1年`、`…-季平衡-近10年`… 全是复制品 | `四资产等权`、`红利+债`… 才是真正的"方案" |

**方案 A 的连带代价**：用户必然需要"复制组合"来对照 → 复制又带来"改了一个、另一个不跟着变"的一致性问题。多组合本可以是"可选的组织能力"，在 A 下会退化成"对照的必需品"。

### 1.3 一个问题就能定

> **"同一组标的，换个再平衡方式，算不算另一个组合？"**
>
> 算 → **A** ｜ 不算（它只是换个口径看同一组持仓）→ **B**

**韭圈儿的选择明确是"不算"**：同一个组合页面上三个 tab 切，区间也是同一页里填自定义日期。所以它的「再平衡 / 区间」天然是**看的角度**，不是组合的属性。

### 1.4 修正后的字段归属

| 归属 | 表 | 字段 |
| --- | --- | --- |
| **组合身份** | `portfolio` | `id` / `name` / `note` / `status`(active\|archived) / `created_at` / `updated_at` |
| **组合成员** | `portfolio_asset` | `portfolio_id` / `symbol` / `target_weight`（初始比例） / **`added_at`**（添加日，D4 用） / `sort_order`，唯一键 `(portfolio_id, symbol)` |
| **一次回测的参数** | `backtest_run` | `rebalance` / `benchmark` / `start` / `end` / `algorithm_version` / `input_hash` |

**一句话**：组合只描述"**持有什么、各多少**"；"**怎么算**"属于 Run。

**折中选项（可选）**：`portfolio` 可以存 `default_rebalance` / `default_benchmark`，但**仅用于新建 Run 时预填**，不改变语义——真正的事实来源始终是那次 Run 的参数。

> 顺带说明 D4：`added_at` 必须放在**成员表**而不是标的主表——因为**同一个标的在不同组合里的添加日是不同的**。

## 二、完全不变的部分（边际复杂度 = 0）

这是多组合最重要的好消息，值得逐条确认：

| # | 项 | 为什么不变 |
| --- | --- | --- |
| 1 | **回测引擎与算法** | 份额法账本 + 三种再平衡是 `(成员, 权重, 区间, 再平衡方式) → NAV` 的纯函数，多组合只是多调用几次 |
| 2 | **统一序列层 `get_series`** | 输入是 `(asset_id, start, end)`，与"属于哪个组合"无关 |
| 3 | **标的注册表 `research_security`** | `symbol` **全局唯一** → 一只标的被 N 个组合引用，**只抓一次、只存一份** |
| 4 | **定时同步任务** | 按 `enabled=True` 遍历标的，**与组合无关** → **多组合不增加任何抓取量、不增加同步任务** |

> ⭐ 第 3、4 条是多组合最容易低估的优势：**组合数增加，数据成本不变。** 10 个组合共用 30 只标的，抓取量还是 30 只。

## 四、页面结构

```
L1  /portfolio-lab         组合列表（管"组合"）
L2  /portfolio-lab/{id}    组合详情（复刻韭圈儿，管"标的与回测"）
```

分层很干净：**列表页管"组合"，详情页管"标的与回测"。**

### 列表页（L1）—— ✅ 已按韭圈儿实拍截图对齐

> **完整规格见 `docs/portfolio-lab-page-spec.md` §九**（用户 2026-09-19 提供实拍截图）。
> ⚠ 此前本节凭常识写的"表格 + 标的数 + 可用区间 + 回撤 + 排序/搜索"**全部作废** —— 韭圈儿列表页比那轻得多。

**实测形态**：页面标题 `组合回测`；主区标题 `我的组合`；右上**唯一按钮** `创建组合`；主体是**两列卡片网格**。

每张卡片三行：

| 行 | 内容 |
| --- | --- |
| 标题行 | **组合名** + `✎` + 右上角 `删除`（浅灰小字） |
| 元信息行 | `成立时间：YYYY-MM-DD`（左）· `收益时间：YYYY-MM-DD`（右） |
| 指标行 | **三格**：`日收益` / `近一月` / `今年以来`（大字数值 + 小字标签，**涨红跌绿**） |

**没有**的东西（照韭圈儿，不要加）：排序、搜索、筛选、分组、标的数、可用区间、回撤、净值曲线、左侧内嵌导航。

**关键一致性约束**：列表页这三格 = 详情页收益条的三个子集，**数字必须相同**（实测截图 `-0.62%` / `6.67%` 与详情页完全一致）→ 必须共用同一条计算路径。

**交互已闭合**（用户 2026-09-19 确认；明细见 `page-spec` §9.4）：

| 操作 | 结论 |
| --- | --- |
| **进入组合** | **点卡片本体**即可进入 |
| 创建组合 | 直接创建 + **默认名**（`我的组合N`），进详情页后可改名 |
| **复制组合** | 列表页提供，**卡片级操作**（hover 时显示）；自动命名 `复制_原名` |
| `✎` | **就地改组合名**（inline 编辑） |
| `删除` | **软删（可恢复）+ 二次确认**；不级联删标的、不删 Run |
| 空组合 | 三格显示 **`—`**，不显示 `0.00%` |

### ⚠ 一个必须提前定的实现要点：列表页指标**不能现算**

（明细见 `page-spec` §9.6）

- 三格是**固定参数**（不平衡 + 三个固定区间）的结果 → **天然可缓存**；现算则耗时随组合数线性增长。
- ⭐ **截图本身就在暗示这件事**：卡片上的 `收益时间：2026-09-18` 正是"**这批指标算到哪一天**"——它的存在意义就是标注缓存的**数据截止日**。
- 方案：`portfolio` 冗余 4 个字段（3 个收益 + 1 个 `cached_asof_date`）；每日定时任务末尾重算，新建/复制时立即算一次。
- ⚠ **不要复用 `backtest_run`**：Run 参数各异（可能季平衡/自定义区间），而列表页固定「不平衡 + 默认三区间」——但两者必须算出同样的数字（这正是 §9.3 的验收点）。

### 详情页内的"组合切换"（可选便捷入口）

L1 已经是列表，详情页顶部再加一个组合下拉属于**便捷跳转**（不返回列表即可切），保持当前再平衡/区间选择。
**建议**：低优先，列表页够用就可以先不做。

## 五、多组合真正解锁的能力：跨组合对照

| 对照 | 韭圈儿怎么做 | 我们 |
| --- | --- | --- |
| **同一组合的不同再平衡** | 页面上切换（不平衡/季/年） | ✅ 同页面切换（Run 参数，**不建多个组合**） |
| **不同资产配置的对照**（四资产等权 vs 红利+债 vs 全天候） | 做不到（只能逐个看） | ⭐ **多组合 + 跨组合对比**（我方的真正增量） |
| 跨组合对比的注意点 | — | ⚠ **区间必须可比**：不同组合的共同起点不同（受各自最晚标的制约）→ 对比时需"**对齐到交集区间**"开关，且明确标注 |

**建议**：跨组合对比排**二期**（先把单组合 + 列表跑通）。但数据模型**一期就要支持**（`backtest_run` 带 `portfolio_id` 即可）。

## 六、风险清单（5 条，都要在实现时挡住）

| # | 风险 | 处理 |
| --- | --- | --- |
| 1 | **删标的影响面** | 软删标的（`enabled=False`）会影响 **所有**引用它的组合 → UI 必须提示"该标的被 N 个组合使用"，且**不允许从标的主表删** |
| 2 | **从组合移除 ≠ 停用标的** | 只删 `portfolio_asset` 行。否则会顺带毁掉 `/research` 模块与定时同步 |
| 3 | 删组合 | 建议**软删（archived）+ 可恢复**，不级联删标的、不级联删 Run（保留历史） |
| 4 | **Run 数量膨胀** | Run = 组合数 × 再平衡方式 × 区间。原来 D10（Run 幂等）只是体验问题，多组合后变成**必须做**：同 `(portfolio_id, rebalance, start, end, algorithm_version)` 复用已有 Run |
| 5 | 组合内同一标的重复 | 唯一键 `(portfolio_id, symbol)` → 禁止重复（"黄金 10% + 黄金 15%"没有意义，且会让权重语义含混） |
