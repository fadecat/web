## 二、区域详解

### 区域① 收益条

一行七格，**首格放大**（字号约为其余 2 倍），标签在下。

| 格 | 标签 | 取值规则 | 示例（本组合） |
| --- | --- | --- | --- |
| 1 | 近1日 | `Σ wᵢ × rᵢ(各自最新可用日)`，QDII 按前一日补偿 | **1.08%** |
| 2 | 近1周 | 自然日回推 7 天 → 向前对齐交易日 | −0.41% |
| 3 | 近1月 | 同上，回推 1 个月 | −0.62% |
| 4 | 今年来 | 上年最后交易日 → 末端 | 6.67% |
| 5 | 近1年 | 回推 1 年 → 向前对齐 | 10.40% |
| 6 | 近3年 | 回推 3 年 | 53.51% |
| 7 | 成立来 | **建仓日 T0（= 各标的"数据可得区间"的共同起点）→ 末端**。⚠ 与韭圈儿存在起算日口径差异（它自成立日面值起算）→ 差约 1.3pp | 333.80%（韭圈儿）/ 335.07%（本引擎） |

**颜色规则（A 股习惯）**：涨 **红**（`#E63946` 一类）、跌 **绿**（`#2A9D8F` 一类）、零 **灰**。
**关键约束**：所有格子的数值由**同一条净值序列**导出——即"从建仓日 T0 等权建仓、不平衡持有至今"的那条曲线。**不允许为每个区间单独重新建仓。**

### 区域② 组合收益 Tabs

| Tab | v1 | 说明 |
| --- | --- | --- |
| 收益详情 | ✅ 做 | 净值曲线 + 区间指标（本规格主体） |
| 组合回撤 | ✅ 做 | 回撤曲线 + 最大回撤标注（峰/谷/修复日） |
| 组合大爆炸 | ❌ 不做 | 需基金季报持仓穿透，另需数据源 |
| 组合实盘 | ❌ 不做 | 绑定真实持仓，与回测语义冲突 |

### 区域③ 控制条

```
再平衡 ⓘ : ( ) 不平衡   ( ) 季平衡   ( ) 年平衡
自定义   : [起始日] - [结束日]        [ 组合回测 ]
```

- 三选一，默认 **不平衡**。
- `ⓘ` 悬浮提示（文案取自韭圈儿官方说明）：
  > 季平衡：每个季度 1 日（如遇节假日会自动延期至下个交易日），会将组合基金的比例调整至初始设定的比例，超出初始比例的基金卖出，低于初始比例的基金买入。
  > 年平衡：每年 1 月 1 日（同上）。
- **起始日规则 = 共同**：若用户选的日期早于共同起始日，**自动前移**并在输入框旁提示"实际起始：YYYY-MM-DD"。**不报错、不静默改模式。**
- 点击 `组合回测` 才发起计算（表单 draft / applied 分离）。
- **成交价口径提示**（固定文案，放在控制条下方或 tooltip）：`成交价＝当日净值确认（T 日 15:00 前提交）。含 QDII 净值滞后补偿。`

### 区域④ 净值曲线

- **纵轴**：收益率%（**以区间起点归一为 0%**，写死；不随再平衡方式变化），自动分档。
- **横轴**：年份刻度。
- **主曲线**：本组合（红）。
- **对比曲线**：**可选，不是固定值**（用户 2026-09-19 裁决：主要做基准对照，跟红利、任意 ETF、个股都可以比）。候选包括红利指数系列、任意 ETF/个股；默认值待定（倾向沪深300，与韭圈儿一致）。
  - ⚠ 沪深300 是**价格指数**（不含股息），与含分红的组合口径不同 → 图例与 tooltip 必须标注口径差异。
- 图例在下方：`■ 本组合  ■ <对比标的名称>`。
- 右上角：
  - `去添加基金对比 ▼` —— 我方增强为 `去添加对比标的`（支持个股 / ETF / 场外基金）
  - `● 查看完整曲线 ⓘ` —— **v1 不实现**（该模式起点为"成立最久的标的"，未成立者按空仓；与"共同"起点规则互斥，且"空仓"语义未验证）。按钮保留但置灰 + 提示"暂不支持"。
- 悬浮 tooltip：日期 + 本组合累计收益 + 对比标的累计收益。

### 区域⑤ 指标卡（我方增强，韭圈儿无此区）

| 指标 | 口径 |
| --- | --- |
| 年化收益 CAGR | `(末/初)^(1/年数) − 1` |
| 最大回撤 | 区间内 `min(NAV/cummax − 1)`，附峰值日 / 谷值日 / 修复日 |
| 年化波动 | 日收益标准差 × √244 |
| Sharpe / Sortino | 无风险利率默认 0 |
| Calmar | CAGR / |最大回撤| |
| 最差年度 / 最差月度 | 按自然年 / 自然月重采样 |
| 最长恢复天数 | 从谷值回到前高所需交易日数 |
| 累计换手 | `Σ|Δw|`，**不参与收益计算**（零成本口径下仅作实盘可行性参考） |

> 该区为增强项，**不影响区域①⑦与韭圈儿的对齐**。若需要严格一致性验收，可折叠该区。

### 区域⑥ 相关性矩阵

- 标题右侧 `ⓘ`，下方**显式标注计算区间**（本例 `2016-09-19~2026-09-18`）。
- **注意**：相关性区间的起点对齐方式与回测**不同**（回测向前对齐到 09-14，相关性向后顺延到 09-19）。同一天回推 10 年，两个模块给出不同答案——**实现时两处分别处理，不能共用同一个"区间解析"函数**。
- 单元格着色：`+1` 深红 → `0` 白 → `−1` 蓝；对角线深红且显示 `1`。
- 行列表头 `1 2 3 4` + 左侧带序号的标的名称（两行：名称 + 代码）。
- 底部色带图例：`正相关 —— 负相关`。
- **不随再平衡方式变化**（三种模式共用同一矩阵）。

### 区域⑦ 组合详情表

| 列 | 内容 | 口径 |
| --- | --- | --- |
| 基金名称 | 名称 + 代码（两行） | 我方增强：加**资产类型徽标**（股票 / ETF / 场外）。**个股/ETF 该列的"基金经理"子栏留占位符 `—`**，待定义 |
| 日涨幅 | 日涨跌幅% + **该净值所属日期**（小字） | 各标的自身最新可用日；QDII 会滞后一天 |
| 添加后的收益 | 自**该标的添加日**至今的累计收益 | **纯展示列，对回测零影响**。v1：添加日 = 用户添加操作时间；v2：允许编辑为历史日期。用途＝账本核对 / 择时复盘 / 真实持仓视角（详见歧义审计 D4） |
| 比例（初始） | 初始设定权重 | 本例 25.00% × 4 |
| 比例（当前） | 不平衡持有至今的**漂移权重** | 本例 11.43 / 20.30 / 11.11 / 57.16 |
| 基金经理 | **场外基金**：蛋卷 `/djapi/fund/{code}` → `manager_name`（实测与韭圈儿完全一致）。**个股 / ETF：留占位符 `—`，待定义**（韭圈儿无此场景；见歧义审计 V2） | 场外可用；场内待定义 |

## 八、接口契约与字段映射（实现前须定义）

原则：**页面要什么，接口就定义什么**。不要让前端"接口给什么就显示什么"——否则会出现页面缺列、口径由接口倒推的问题。

| 页面区域 | 端点 | 关键响应字段 |
| --- | --- | --- |
| ① 收益条 | `GET /api/portfolio/backtests/{run_id}` | `windows: {d1, w1, m1, ytd, y1, y3, inception}`，每项含 `value` 与 `actual_start` |
| ② 组合收益 Tabs | 同一份数据 | `mode: "nav" \| "drawdown"` 由前端切换，不额外请求 |
| ③ 控制条 | `POST /api/portfolio/backtests` | 请求 `{portfolio_id, rebalance, start, end}`；响应 `run_id` + **`effective_start`** |
| ④ 净值曲线 | `GET .../{run_id}` | `nav_series: [{date, value, benchmark_value}]`、`benchmark: {code, name, return}` |
| ⑤ 指标卡 | 同上 | `metrics: {cagr, mdd, vol, sharpe, sortino, calmar, worst_year, worst_month, recovery_days, turnover}` |
| ⑥ 相关性矩阵 | 同上 | `correlation: {start, end, symbols, matrix}`（**区间与回测区间分开传**） |
| ⑦ 组合详情表 | `GET /api/portfolio/portfolios/{id}` | `assets: [{symbol, name, asset_class, day_return, day_return_date, since_added_return, target_weight, current_weight, manager}]` |
| ⑧ 口径提示 | 静态文案 | — |

**四条必须遵守的约定**：

1. **`effective_start` 必须回传** —— 起点规则是"共同"，用户选的更早日期会被**自动前移**，前端要如实回显。
2. **`correlation.start` ≠ 回测区间起点** —— 韭圈儿两个模块的对齐方式不同（回测向前对齐、相关性向后顺延），**必须分开传**，不可共用同一个区间解析。
3. **`current_weight` 与 `since_added_return` 是两套数据** —— 前者是"不平衡持有至今的漂移权重"，后者是"各标的自其添加日起算"。**不要合并成一个字段或共用一个起点。**
4. **百分比单位在契约里写死** —— 统一传小数（`0.1040`）或统一传百分数（`10.40`），二选一并写进 schema，避免前端二次换算出错。

> 端点全表见 `docs/portfolio-lab-flow.md` 第四节。**注意**：该节仍有效，但其中"再平衡规则含月/阈值"的旧表述已作废。

### 9.3 三条与详情页的一致性约束（重要）

1. **列表页的指标 = 详情页收益条的三个子集**（`日收益`≈近1日、`近一月`=近1月、`今年以来`=今年来）。
   实测截图：`-0.62%` / `6.67%` 与详情页**完全一致**，`1.0829%` ≈ 详情页 `1.08%`。
   → **验收时必须校验：同一组合，列表页与详情页这三格数字相同。**
2. **涨红跌绿**（`1.0829%` 红、`-0.62%` 绿）→ 符合 A 股习惯 ✅ 无需改动。
3. ⚠ **数值精度不统一**：`日收益` 给 **4 位小数**（`1.0829%`），`近一月`/`今年以来` 给 **2 位**（`-0.62%` / `6.67%`）。
   实现时**建议统一为 2 位**（或在契约里写死各自精度）—— 否则前端会不一致。见 9.4 待确认。

### 9.6 列表页三格指标怎么算（⚠ 之前漏写的实现要点）

**① 口径必须与详情页共用同一条计算路径**

列表页的 `日收益 / 近一月 / 今年以来` = 详情页收益条的**三个子集**（近1日 / 近1月 / 今年来）。
→ **必须调用同一个「区间解析 + 份额法账本」实现**，不能各写一套。否则"自然日回推 → 向前对齐交易日"这类规则只要有一处不同，两页数字就会不一致 —— 而那正是 9.3 要验收的地方。

**② 必须是"缓存 + 每日刷新"，不能每次打开列表现算**

理由：
- 这三格是**固定参数**（不平衡 + 三个固定区间）的结果，**不随用户交互变化** → 天然可缓存。
- 若现算：N 个组合 = N 次回测，耗时随组合数线性增长。
- ⭐ **截图本身就在暗示这件事** —— 卡片上的 **`收益时间：2026-09-18`** 正是"**这批指标算到哪一天**"，它存在的意义就是标注缓存的**数据截止日**。

**设计**：

```
缓存位置   portfolio 上冗余 4 个字段（或单独一张 portfolio_latest_metrics）
           cached_day_return / cached_month_return / cached_ytd_return / cached_asof_date
刷新时机   ① 每日定时任务末尾（净值落库后重算全部组合）—— 复用 17:30 链路
           ② 新建 / 复制组合时立即算一次（此时只有 1 个组合，成本低）
失效条件   组合成员或权重变更 → 标记待重算（最迟次日刷新）
```

> ⚠ **不要直接复用 `backtest_run` 的结果**：Run 是按需触发、参数各异的（可能是季平衡或自定义区间），而列表页固定用「不平衡 + 默认三区间」。
> 但两者**必须算出同样的数字** —— 这正好是 9.3 的验收点。
>
> 这条也顺带解释了两个设计选择的由来：**为什么列表页固定用不平衡**（否则缓存键太复杂）、**为什么卡片要显示"收益时间"**（标注缓存新鲜度）。
